# Единый шаблон статей RESET

Эталон: статья «Стоимость разработки с AI». Все статьи используют `templates/articles/render.mjs`, стили `materials/article-editorial.css` и поведение `materials/article-editorial.js`.

## Новая статья

```sh
npm run new:article -- --locale ru --category development --slug novaya-tema --title "Название статьи"
```

Команда создаёт папку `content/articles/ru/development/novaya-tema/` с двумя файлами:

- `article.json`: заголовок, описание для поиска, лид, изображение с alt, даты, статус, связанные материалы и дополнительные блоки.
- `body.html.inc`: только содержание статьи. Заголовки разделов оформляются как `<h2 id="stable-anchor">...</h2>`. Стабильные якоря сохраняем при редактировании.

```sh
npm run build:articles
npm run check:articles
npm test
```

Сборка генерирует страницы на всех заведённых языках. Русский источник также генерирует старый адрес `/materials/.../`, canonical ведёт на `/ru/materials/.../`. Редактировать сгенерированные `index.html` вручную нельзя: следующая сборка заменит изменения.

## Что включено автоматически

Обложка, хлебные крошки, автор, дата при наличии, расчёт времени чтения, нумерация разделов, оглавление для телефона и компьютера, прогресс, кнопки поделиться, форма с идентификатором статьи, рекомендации опубликованных материалов на том же языке, canonical, Open Graph, Article и BreadcrumbList.

Текст остаётся индивидуальным. Цены, процесс, таблицы и иллюстрации добавляем там, где они раскрывают тему. Не переносим цены разработки в маркетинговые статьи.

## Поля article.json

Обязательные: `locale`, `category`, `slug`, `status`, `title`, `description`.
Дополнительные: `seoTitle`, `deck`, `datePublished`, `dateModified`, `hero` (`src`, `alt`, `caption`), `contactTitle`, `contactText`, `related`, `blocks`.

`related` содержит идентификаторы вида `ru/marketing/seo-nedvizhimost-2026`. При пустом списке выбираются до трёх других опубликованных статей на языке страницы. Даты записываются как YYYY-MM-DD только при наличии фактической даты.

`status: draft` показывает отметку о подготовке и устанавливает noindex. Публикация: закончить текст, проверить факты и ссылки, поставить `status: published`, указать реальную дату, собрать и проверить страницу. Переводы ведутся отдельными источниками; готовность русского текста не означает готовность перевода.

## Дополнительные блоки

В тексте ставим `<!-- block:budget -->`, в `article.json` добавляем:

```json
"blocks": {
  "budget": {
    "type": "table",
    "caption": "Состав проекта",
    "columns": ["Этап", "Результат"],
    "rows": [["Прототип", "Согласованные сценарии"]]
  }
}
```

Доступны `prices` (items: title, price, description; note), `table` (caption, columns, rows), `steps` (items: title, html, result), `note` (title, text), `image` (src, alt, width, height, caption), `related` (url, title, label), `faq` (items: question, answer), `sources` (items: title, url). Общая реализация в `templates/articles/blocks.mjs`. В `html` допускается только доверенная редакционная разметка из репозитория.

## Редакционные правила

Сначала даём ответ на вопрос читателя. Затем объясняем причины, варианты, ограничения, процесс и следующий шаг. Пишем конкретно, сохраняем голос RESET. Используем дефис вместо длинного тире. Избегаем конструкций «не X, а Y», пустых вступлений и обещаний гарантированного результата. Цифры снабжаем первоисточниками, датами и контекстом исследования. Иллюстрации описываем содержательным alt. Не выдаём изображение за фотографию команды без подтверждения. Внутренние ссылки ведут на существующие материалы.

## Проверка перед выпуском

Проверить мобильный и широкий экран, оглавление, таблицы, изображения, FAQ и форму без отправки тестовых обращений. Проверить отсутствие потери текста. Запускать сборку статей после массовых операций с общим UI. Изменение шаблона применяется ко всем статьям одной сборкой.

## Стартовый состав журнала

Состав навигации задаёт `content/journal.json`: три раздела и девять тем. После изменения названий или статуса статьи запускайте `npm run build:articles` и `npm run build:journal`. Готовые статьи открываются из карточек, будущие темы показаны с пометкой подготовки без ссылки на черновик. Не добавляйте отложенные темы в стартовую навигацию автоматически. Их исходники и прежние адреса сохранены.

Следующая статья: «CRM для агентства недвижимости: готовая система или индивидуальная разработка». Затем автоматизация заявок и AI-ассистент. Раздел разработки содержит три опубликованные статьи.

## Согласованный порядок публикации

После вводных пользователя и необходимых уточнений готовим финальную версию, проверяем и сразу публикуем. Дополнительное согласование готовой статьи не требуется. Статус draft используем для ещё не написанных тем или по прямой просьбе пользователя. При публикации обновляем журнал, блок на главной и sitemap.xml; переводы публикуем только после подготовки их текста.

## Индексация после релиза

После `build:articles` запускать `build:journal`: он применяет правила индексации и пересобирает sitemap. Отдельная команда: `npm run build:seo`. В sitemap входят только уникальные canonical-адреса готовых страниц. Раздел без опубликованных статей получает noindex,follow автоматически; после первой публикации ограничение снимается. Черновики и переводы не открываются для поиска автоматически вслед за русским оригиналом. Не закрывайте их обход в robots.txt: поисковик должен прочитать noindex.
