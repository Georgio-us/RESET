# RESET: индексация действующих страниц

Дата пересмотра: 26 октября 2026.

## Наблюдения

В опубликованном `sitemap.xml` 141 URL. Отчёт Search Console, обновлённый 23 октября, показывает 18 проиндексированных страниц; основная оставшаяся группа — «Обнаружена, не проиндексирована». В ней нет даты последнего сканирования у показанных URL. Это не доказывает санкцию за AI-контент и не означает, что Google прочитал каждую страницу и отказал ей. Google не публикует безопасный недельный лимит страниц.

Текущие URL уже доступны и известны Google. Удаление sitemap, временные 404/`noindex`, смена URL или расписание повторного открытия этих же страниц не сбросят историю обнаружения. Удаление из sitemap само по себе не запретит обход URL по внутренним или внешним ссылкам. Google прямо советует не вращать карты сайта и не использовать временное скрытие страниц для перераспределения обхода. Не применять эти меры массово ради вида «постепенного запуска».

26 октября по запросу владельца запущен ограниченный эксперимент: четыре языковые версии кейса SHEPIT / Kommo CRM перенесены на новые URL с уточнением текста. Старые URL направляются постоянным редиректом на соответствующие новые. `content/seo-sitemap-cohort.json` фиксирует 18 URL, отмеченных индексированными в экспорте Search Console 23 октября, и четыре новых URL пилота. Текущая карта сайта содержит только эти 22 адреса. Остальные действующие страницы остаются доступными, индексируемыми и связанными с сайтом; отсутствие в sitemap не делает их невидимыми для Google. Это измеримый тест, а не способ обнулить известные Google URL или гарантия индексации.

По отдельному запросу владельца подготовлена следующая партия: четыре версии услуги Meta Ads, включая новую страницу на испанском. После содержательной правки и проверки она автоматически откроется 2 ноября 2026 года в 09:00 UTC через работающий на Railway сервер. В этот момент три прежних адреса услуги начнут направлять на новые прямым 301, новый испанский адрес станет доступен, а сервер дополнит XML- и HTML-карты сайта и внутренние ссылки. До выпуска старые страницы остаются доступными, новые адреса отвечают 404. Очередь и дата находятся в `content/seo-release-queue.json`; состояние проверяется `npm run check:seo-queue`. Остальные услуги отмечены как `needs-editorial` и не будут выпущены без подготовленного содержимого и проверенных переводов. Никаких запросов индексации или проверки факта индексации этот сервер не выполняет.

Источники: [обзор sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview), [диагностика обхода](https://developers.google.com/search/docs/crawling-indexing/troubleshoot-crawling-errors), [запрос повторного обхода](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl), [политика против массового малоценного контента](https://developers.google.com/search/docs/essentials/spam-policies).

## Работа с существующими URL

1. Сохранять проиндексированные URL и их контент доступными. Перед адресным исключением другого URL проверять его фактический статус в Search Console, трафик, внешние ссылки и роль для пользователя. Список в отчёте обновляется с задержкой.
2. Сверить каждый URL sitemap с ответом 200, self-canonical, отсутствием `noindex`, правильным `hreflang` и фактической ссылкой с доступной HTML-страницы. Проверить мобильную версию и серверные логи Googlebot по приоритетным URL.
3. В первую очередь разбирать коммерческие услуги, затем подтверждённые кейсы и полезные статьи. Для каждой страницы фиксировать URL, текущий статус, дату последнего обхода, внутренние ссылки, содержание и конкретное исправление. Сравнить с 18 URL, которые уже индексируются.
4. Исправлять реальные проблемы: пустой или повторяющийся основной текст, неверные утверждения, битые ссылки, блокировку ресурсов, ошибки ответа сервера. Действительно ненужные страницы исключать только после адресного анализа. Полные переводы одного материала могут описывать тот же проект на разных языках.
5. После значимого исправления проверить живой URL и наблюдать фактический обход и индексацию. Запрос индексирования использовать выборочно; повторные запросы одного URL не ускоряют обход. Обновлять sitemap только при реальном изменении состава или даты существенного изменения страницы.

Ни один из этих шагов не гарантирует срок или факт индексации. Автоматический мониторинг можно разместить в облаке, но он не должен массово менять доступность страниц или симулировать новые даты публикации.

## Будущие материалы

Новые материалы выпускать после проверки фактов, подлинности кейсов, пользы для посетителей, полноценности переводов, мобильного вида, ссылок и формы. Черновики держать вне навигации и sitemap. Не задавать искусственный интервал публикации как средство обхода спам-фильтра. Содержание и назначение страницы важнее календаря.
