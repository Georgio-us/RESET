# Международная структура RESET

## Целевая схема URL

| Язык | Главная | Кейсы |
| --- | --- | --- |
| Русский | `/ru/` | `/ru/cases/<slug>/` |
| Украинский | `/uk/` | `/uk/cases/<slug>/` |
| Английский | `/en/` | `/en/cases/<slug>/` |
| Испанский | `/es/` | `/es/cases/<slug>/` |

Корневой `/` не должен быть самостоятельной индексируемой версией. После выбора основной аудитории он должен отдавать 301 на `/ru/` либо стать `x-default` с редиректом по выбору пользователя.

## До публикации

- Сервер должен отдавать `200 OK` по каждому языковому URL, а не выполнять клиентский перевод после `?lang=…`.
- Для каждой страницы нужны собственные переведённые `title`, `meta description`, основной `h1` и текст в HTML, доступный без JavaScript.
- На каждой языковой версии размещаются `canonical` на саму себя и полный комплект `hreflang`: `ru`, `uk`, `en`, `es`, `x-default`.
- В `sitemap.xml` перечисляются все языковые URL; в `robots.txt` — ссылка на sitemap.
- Слаг кейса сохраняется одинаковым между языками, чтобы связь переводов была однозначной.

## Текущее состояние

В интерфейс добавлена маршрутизация локали: украинские переходы формируют `/uk/...`, а не `?lang=uk`. В `<head>` главной добавлены `canonical` и `hreflang` для четырёх будущих языковых версий.

Для полноценной индексации нужно знать хостинг и сгенерировать статические файлы для каждого маршрута. Конфигурация rewrite зависит от платформы, поэтому её нельзя корректно выбрать без информации о деплое.
